# Contributing to Laravel AI Security Masterclass

Thank you for your interest in contributing to **Laravel AI Security Masterclass**! We welcome contributions from developers, security researchers, and DevOps engineers of all experience levels.

---

## Code of Conduct

Please maintain a professional, respectful, and inclusive environment. Harassment of any kind will not be tolerated.

---

## How to Contribute

### 1. Reporting Security Vulnerabilities

> ⚠️ **IMPORTANT**: Do NOT report security vulnerabilities via public GitHub issues.

Please follow our [Security Policy](SECURITY.md) and report vulnerabilities via:
- **GitHub Private Security Advisories**: [Report a Vulnerability](https://github.com/Umar-444/Laravel-AI-Security-Masterclass/security/advisories/new)
- **Email**: [contact@itsumarfarooq.com](mailto:contact@itsumarfarooq.com)

---

### 2. Suggesting Enhancements or New Topics

We are actively expanding coverage across:
- **PHP 8.4+ & Laravel 13+ security features**
- **AI / LLM security in Laravel** (prompt injection defense, RAG security, rate limiting AI endpoints)
- **OWASP Top 10 (2025) & OWASP API Top 10 (2023)**
- **Modern authentication** (Passkeys / WebAuthn, FIDO2, OAuth 2.1)
- **Zero Trust, Supply Chain, and Post-Quantum Cryptography**

To propose a topic, open a feature request in [GitHub Issues](https://github.com/Umar-444/Laravel-AI-Security-Masterclass/issues) or join [Discussions](https://github.com/Umar-444/Laravel-AI-Security-Masterclass/discussions).

---

### 3. Submitting Pull Requests

1. **Fork the repository** on GitHub.
2. **Clone your fork** locally:
   ```bash
   git clone https://github.com/<your-username>/Laravel-AI-Security-Masterclass.git
   cd Laravel-AI-Security-Masterclass
   ```
3. **Create a topic branch**:
   ```bash
   git checkout -b feature/my-security-topic
   ```
4. **Adhere to standards**:
   - Use PHP 8.4+ syntax (typed properties, readonly classes, `array_find()`, match expressions).
   - Use modern Laravel 13 practices (`bootstrap/app.php` middleware, Form Requests, Sanctum 4.x, Policies).
   - Provide vulnerable vs secure side-by-side examples with clear explanations.
   - Never recommend deprecated functions (`md5()`, `sha1()`, `rand()`, `X-XSS-Protection`).
5. **Commit your changes**:
   ```bash
   git commit -m "docs: add AI prompt injection mitigation guide"
   ```
6. **Push and submit PR**:
   ```bash
   git push origin feature/my-security-topic
   ```
   Open a Pull Request against the `main` branch.

---

## Style Guidelines

- **Markdown formatting**: Use clean headers, bullet points, code fences with syntax highlighting (`php`, `bash`, `json`), and note boxes (`> [!NOTE]`, `> [!IMPORTANT]`, `> [!WARNING]`).
- **PHP Code formatting**: Follow PSR-12 and PER Coding Style 2.0 standards.
- **Tone**: Professional, authoritative, educational, and developer-friendly.
